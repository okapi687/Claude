## コードの構成

### 実行のしかた

ノートブックは `研究/` をカレントディレクトリとして動かし、`from model.MAM_basic_ex_v2 import SoldierCrabSwarm_ex_v2` のように読み込む（`%autoreload 2` を使用）。どのモデルも使い方は同じ:

```python
swarm = SoldierCrabSwarm_ex_v2(N=100, S=50, L=4, P=10, alpha=0.1, R_Nf=2, R_M=3, c=2, seed=46, int_mode="floor")
swarm.step()                                   # 1ステップ進める
history = swarm.run(600, record_history=True)  # 位置の履歴 (T+1, N, 2) を返す
swarm.position                                 # (N, 2) の整数座標。S×S のトーラス上
```

`model/MAM_support.py` の `SwarmVisualizer(swarm)` で `summary()`、`animate()`、`save_snapshot()` ができる。

### 2つの系統

| 系統 | 最新版 | 内容 |
|---|---|---|
| 論文1（速度一致あり） | `MAM_basic_ex_v2.py`（`ex_fix` と同じ内容で名前を変えたもの） | 全員の相互予期 → 全員の追従 → 全員の自由移動、の順にフェーズを回す。その後、半径 R_M の速度一致で基本ベクトルの向きをそろえる |
| 論文2（速度一致なし） | `MAM_basic_Murakami.py` | 付録の式(1)〜(13)どおり。基本ベクトルの向きを、直前の移動 V と ω で更新する（q = V_u + ω·v_u） |

`MAM_basic_v1.py`（11/18）は2つの最新版を1つにまとめたもの。`model="paper1"` / `"paper2"` で切り替える。論文2の既定は `omega_on="velocity"`（ω を移動の向き側に掛ける）で、`"principal"` にすると Murakami と同じになる。検証の経緯と結果は `研究/paper/検証レポート.md` にまとめてある。

それ以外のファイル（`MAM_basic_step*`, `*_noVM`, `*_pop*`, `recalc`, `dynamic`, `mix`）は途中で試した版。比較のために残しているので、**消したり書き換えたりしない**。新しく試すときは、新しいファイルを作るか、最新版にオプション引数を足す（最新版は元の挙動に戻せるオプションを持つ形にしている）。

### 最新版にある切り替えオプション

- `ex_v2`: `int_mode`（floor / ceil / round / trunc / stochastic）、`ma_rule`（sequential / literal）、`follow_chain`（追従の連鎖を許すか）、`free_wait`
- `Murakami`: `int_mode`（初期値 round）、`dedupe_votes`、`spv_mode`、`static_vacancy`、`tiebreak`
- `v1`: 上の2つに加えて、`alpha_scale`（α の範囲を何倍に読むか、既定 1）、論文1の `choose_by`（同率サイト・自由移動を遷移単位 "vector" かサイト単位 "site" で選ぶ、既定 "vector"）、`vm_source`（速度一致で平均するもの："theta" 基本ベクトルの向き＝既定、"unit_disp" 移動の単位ベクトル、"disp" 移動ベクトルそのもの）

floor にすると遷移ベクトルが平均 (−0.5, −0.5) だけ左下にずれる。2つの最新版で `int_mode` の初期値が違う（ex_v2 は floor、Murakami は round）ことに注意。

### 評価指標（`MAM_valid.ipynb` 内）

- 論文1の整列度 `polarization1`: 変位ベクトルの平均の長さ / L
- 論文2の整列度 `polarization2`: 単位変位ベクトルの平均の長さ
- 論文1の密度 `density` / `density_sliding`: Ls×Ls の窓をトーラス上でずらしたときの最大個体数 / N
- 論文2の密度 `density_paper2`: 周り3×3にいる個体数の平均（自分は含まない）
- 変位はトーラスをまたいだ分を `(d + S/2) % S - S/2` で補正する。`ex_v2` は `last_displacement` に補正済みの変位を持つ。
- 最初の 100〜200 ステップは捨ててから平均している。

## 研究テーマ

ミナミコメツキガニ（soldier crab）の群れを表す**相互予期（mutual anticipation）モデル**を論文の通りに実装する。
その中で論文の図を用いて論文と同じように再現できているかを確認している。
メモでの結論として、**論文1と論文2は別のモデルとして扱う**（論文2のモデルで論文1を走らせると結果が大きく違った）。

## 用語（メモと論文の対応）

| メモでの言葉 | 意味 |
|---|---|
| 基本ベクトル | 各個体が持つ基本の移動方向・長さ（L）。更新してはいけない、という指摘があった |
| 可能的遷移 | 基本ベクトルから作る遷移先の候補 |
| 人気度 | 各セルが遷移先として何回選ばれたか。埋まっているセルは最初から -1 として扱う方針 |
| 相互予期 | 人気度が一番高いセルへ遷移する、モデルの中心となる処理 |
| 追従 (Following) | 追従者近傍（Nf）の中で、相互予期で動いた個体が空けたセルへ移動する処理（最新版。追従で空いたセルへの連鎖はしない） |
| 自由移動 | 上のどれにも当てはまらないときの移動 |
| 速度一致 | ボイドの alignment に当たる処理。外すと群れができない |
| 整列度 (Polarization) / 密度 (density) | 評価指標。密度は窓の大きさ Ls によって大きく変わる |
| P, α, ω, L, Nf, Ls | 論文のパラメータ（定義は論文を参照。メモでは P=1, 2, 10, 30, 40 や α=0.1, 0.2 で比較している） |

## Git の運用（複数の端末で管理している）

- **作業を始める前に、必ず `git pull` する。** 別の端末での変更を取り込んでから作業する。
- **作業の区切りごとにコミットして、`git push` する。** ファイルを編集して開発メモを更新したら、それを1つの区切りとする。ためこまない。
- push の前にも `git pull` する。ぶつかった（コンフリクトした）ときは、勝手に片方を消さずにユーザーに確認する。
- ノートブック（`.ipynb`）は出力ごと入っていて、ぶつかると直すのが大変。別の端末で同時に編集しない。
- コミットメッセージは日本語で書く。1行目に何をしたか、そのあとに箇条書きで中身を書く。
